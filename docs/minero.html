Qué hace, comprobado con datos

  • Se registra con clave firmada, pide trabajo firmado con nonce y entrega el resultado; el Core lo recalcula y solo entonces paga.
  • Usa todas las GPU a la vez: una cola por dispositivo y un hilo de petición por dispositivo.
  • Detecta VRAM real de cada tarjeta (props.total_memory). Los TOPS que publica son estimados por clase de tarjeta y así se etiqueta; la potencia medida va aparte (gflops_base) y sale de un benchmark al arrancar.
  • Registro propio (worker/minero.log) con fecha por línea, cerrojo de escritura y rotación interna; cero bytes NUL con 8 hilos escribiendo (probado).
  • Diagnóstico de arranque (worker/arranque.log): versiones, GPU, hilos, errores con traceback, aviso ESTERIL si una GPU deja de pedir trabajo y HILO_MUERTO si falta un hilo, con volcado de pilas.
  • No reinicia ni mata nada solo: los avisos son para diagnosticar, no para esconder el fallo.

No probado: AMD (ROCm), Intel, Linux, macOS ni tarjetas de 2–8 GB. La CPU puede añadirse como nodo con KUKIA_USAR_CPU=1, pero en un PC con GPU resta rendimiento.

Requisitos

  • Windows 10/11 con Python 3.10 o superior en el PATH.
  • PyTorch (con CUDA si hay GPU NVIDIA): sin él no se puede calcular ninguna tarea.
  • Un Core accesible: el de este PC (http://127.0.0.1:8300) o uno público.

Instalación y arranque

git clone https://github.com/lordkukone/kukia-node
cd kukia-node
INSTALAR_Y_MINAR.cmd   (un clic: comprueba, mide la GPU y arranca la guardia)
ARRANCAR_MINERO.cmd    (solo el minero, en una ventana)

El primer arranque crea la billetera y deja la contraseña y las 20 palabras en ledger/wallet/RECUPERACION_*.txt. Sin ese fichero no se recupera el saldo.

Diagnóstico

VER_MINERO.cmd                     (qué está haciendo ahora)
type worker\arranque.log           (arranque, ESTERIL, HILO_MUERTO, pilas)
type worker\minero.log             (una línea por tarea, con fecha)

Si aparece ESTERIL cuda:N, copia el bloque PILAS que viene detrás: eso es lo que hace falta para encontrar la causa de M-02.
