Ponte a minar

De cero a un nodo trabajando y cobrando en tu billetera, en cuatro pasos. Abajo tienes el estado real de la red ahora mismo: si el minero oficial está minando, lo ves aquí.

Qué necesitas

  • Python 3.10 o superior (probado con 3.12) y espacio en disco (~3 GB con torch).
  • GPU NVIDIA es opcional: si hay CUDA mina en todas las GPUs a la vez; si no, cae a CPU. Ojo: desde el 23-10-2026 se paga por trabajo (GFLOP), así que una CPU cobra bastante menos por minuto (no es «lo mismo más lento»).
  • Windows o Linux (probado en Windows 11 con dos RTX). En Windows los comandos valen tal cual en Git Bash o PowerShell; macOS no se ha probado.

Los cuatro pasos

1

Descarga el nodo

El zip trae el Core, el minero, la billetera y el relé de métricas: el mismo código que ves en código fuente.

Descargar kukia-node.zipVer en GitHub

2

Instala las dependencias

cd kukia-node
python -m pip install -r requirements.txt

Si no tienes GPU, instala torch solo para CPU (pesa mucho menos):

python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
3

Arranca el Core

El Core es el coordinador: reparte tareas, verifica resultados y lleva el ledger. Escucha solo en tu equipo (127.0.0.1), no se expone a internet.

cd kukia-node/coordinator
python -u -m uvicorn kukia_core:app --host 127.0.0.1 --port 8300

Comprueba que responde: abre http://127.0.0.1:8300/stats. Debe devolver un JSON con nodos, tareas_ok y supply_emitido.

4

Arranca el minero

En otra ventana, a la vista: el minero cuenta cada tarea y, cada minuto, tareas/min, KIA/min, KIA/h y KIA/h por GFLOPS. Detecta las GPUs solo, abre un hilo por GPU y crea su billetera en ledger/wallet/.

cd kukia-node/worker
python -u kukia_worker.py mi_nombre

En Windows también tienes ARRANCAR_MINERO.cmd (arranca y comprueba lo que falta) y VER_MINERO.cmd (mina a la vista, o se queda mirando si ya hay uno trabajando).

Verás líneas como nodo ... listo (cobra en KUK...) y después tarea ... -> OK +0.0031 KIA. Ese KUK... es tu dirección: el pago va directo ahí, no al id del nodo.

Un solo minero. El primero apunta su PID en worker/minero.lock; si abres otra ventana, no mina y te dice qué PID está trabajando (dos mineros en la misma GPU se reparten el cupo y rinden la mitad). Ctrl+C termina lo que tiene en vuelo antes de salir, así no deja tareas colgadas media hora.

Cobra y comprueba

  1. Abre la billetera → pestaña Mi saldo.
  2. Pega la dirección KUK... que imprimió el minero y pulsa Ver saldo.
  3. Si estás en el mismo PC, la web pregunta a tu Core (127.0.0.1:8300) y, si no lo alcanza, enseña el saldo que publica el relé.
El minero reutiliza el id de cada GPU (worker/identidad_minero.json) y barre a la billetera cualquier saldo viejo firmando la transferencia. Reiniciar no pierde nada.

Cómo se comprueba el trabajo

El minero no manda un hash de su cosecha: envía el resultado numérico de la tarea firmado con su clave Ed25519. El Core lo recalcula y solo paga si coincide (con tolerancia relativa en las difusiones). Si no coincide, no cobra y baja su reputación. Por eso la web puede decir “tareas verificadas” sin pedir fe.

Las tareas actuales son pequeñas (milisegundos): la red está en fase de pruebas y el precio por GFLOP, la dificultad y el calendario pueden cambiar, no son una promesa de rentabilidad. No hay precio de KIA todavía.

Cuánto se cobra: por trabajo, no por tarea

Desde el 23-10-2026 el pago va por los FLOPs verificados de cada tarea y no por tarea entregada. Un checksum (0 FLOPs) y una difusión de 20 GFLOP ya no cobran lo mismo, y el tier por VRAM ya no multiplica: se cobra por lo que se calcula.

  • Precio único del minuto: el presupuesto del minuto (1,31 KIA hoy) se reparte entre los GFLOP que entregó la red en el minuto anterior. Ese precio vale para todas las tareas de ese minuto.
  • Pago de una tarea = precio × GFLOP. A 8× trabajo, 8× pago; el reparto es por trabajo, no por orden de llegada.
  • La bolsa del minuto se congela al abrirlo y no se pasa ni un decimal: cuando se agota, el resto del minuto paga 0. Por eso en la ventana ves muchos +0.0 KIA: no está roto.
  • Un checksum cobra 0 salvo que el operador del Core ponga un mínimo por tarea (KUKIA_GFLOP_MIN).

Ejemplo medido el 23-10 (precio del minuto, 0,0042 KIA/GFLOP): una matriz de 0,128 GFLOP paga 0,00054 KIA y una difusión de calor de 0,4 s paga 0,0208 KIA, cuarenta veces más. Por GPU, un minuto con pago por trabajo dio 0,17 KIA/min. Los números de ahora los da el Core en /stats (bolsa_emision.precio_minuto), que cambia cada minuto. La red emite ~1,31 KIA por minuto en total y la última KIA sale el 01-01-2150.

Comprobar la descarga

El zip es un binario: si se corta la descarga, el minero falla de formas raras. Compara su huella con la publicada antes de descomprimir.

# Windows (PowerShell)
Get-FileHash .\kukia-node.zip -Algorithm SHA256

# Linux / macOS / Git Bash
sha256sum kukia-node.zip
cat kukia-node.zip.sha256

La huella buena es la que sirve kukia-node.zip.sha256 en esta misma web (un fichero con el hash y el nombre del zip). Si no coincide no lo ejecutes: vuelve a descargarlo.

Parar, actualizar y quitar

  • Parar el minero: Ctrl+C en su ventana. Termina la tarea en vuelo antes de salir y libera el candado worker/minero.lock.
  • Parar el Core: Ctrl+C en su ventana. Si no responde, comprueba que el puerto queda libre con netstat -ano | findstr :8300.
  • Actualizar: para los dos procesos, descarga el zip nuevo, comprueba la huella y sustituye los .py. No borres ledger/ ni worker/identidad_minero.json: ahí viven tu saldo y la identidad de tus GPUs.
  • Quitarlo del todo: no hay instalador ni servicio de Windows; se borra la carpeta. Antes, copia lo que dice la sección siguiente.

Qué guardar (esto es tu dinero)

  • ledger/wallet/: los ficheros de tus billeteras. La clave va cifrada con DPAPI de tu usuario de Windows.
  • RECUPERACION_<nombre>.txt si lo generaste: contraseña + 20 palabras. En papel, en dos sitios. Con la contraseña y las 20 palabras recuperas la misma billetera en cualquier equipo; sin ellas no hay recuperación.
  • worker/identidad_minero.json: la identidad de tus GPUs (reputación). Si lo pierdes, minas igual, pero empiezas de cero.
  • Si llevas tu propio Core: coordinator/ledger/kukia.db y coordinator/sello_key.txt. Sin la clave del sello no se puede demostrar que el historial es tuyo.

Si algo falla

  • «Address already in use» al arrancar el Core: ya hay un Core en el 8300. Ciérralo o arráncalo con --port 8301 y apunta el minero ahí con la variable KUKIA_CORE=http://127.0.0.1:8301.
  • No detecta la GPU: comprueba python -c "import torch; print(torch.cuda.is_available())". Si sale False, instalaste el torch de CPU o faltan los drivers de NVIDIA. El minero funciona igual en CPU, cobrando mucho menos.
  • «Sin tareas» durante minutos: la cola puede estar vacía o tu nodo es nuevo (los nuevos empiezan con una tarea cada vez). No es un fallo: mira la portada, en el panel En vivo se ve si hay cola.
  • «Core ocupado» o 503: hay otra escritura en curso; el minero reintenta solo. Si se repite mucho, mira la ventana del Core.
  • La web no ve tu saldo: abre la billetera desde este PC (127.0.0.1) o pega en el campo la dirección de tu Core.

Si quieres publicar tus métricas

El relé de esta web es de solo lectura y lo alimenta el operador desde su PC. Si montas tu propia red, el zip incluye publico/relay.js (Worker) y publico/publicar_metricas.py; necesitas tu propio almacenamiento y tu clave: no reutilices la de esta web.
